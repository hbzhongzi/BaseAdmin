# 开发与使用规范

## 安全基线

- 前端路由守卫只负责页面访问体验，**不提供后端安全保障**；所有受保护 API 必须在服务器校验 token 和权限。
- 不要把前端隐藏菜单或路由守卫当成权限控制。

## 前端扩展

1. 在 `src/api/` 新增按业务划分的 API 模块，通过 `src/api/request.ts` 发请求，不在页面组件里重复实现 fetch、token 和错误处理。
2. 在 `src/views/` 新增页面，并在 `src/router/index.ts` 的后台布局子路由中注册。
3. 在 `src/components/SidebarMenu.vue` 的 `menuItems` 数组登记导航，菜单路径必须与路由一致。
4. API 的请求字段、路径、认证方式和返回结构需与后端接口约定保持一致；成功信封为 `{ code: 1, msg, data }`（详见 [`auth-api.md`](./auth-api.md)）。
5. 生产代码不得提交真实密码、token、私钥或环境专属配置；用 `.env.local` / `.env.production` 管理环境地址，不将密钥放入 `VITE_*` 环境变量。
6. 主题与布局相关改动须遵守 [`themes.md`](./themes.md) 的令牌与预设规范。
7. 前端按钮可使用 `v-permission` 做展示控制，但任何业务接口必须在服务端使用权限中间件或等价逻辑再次校验。

当前版本采用单管理员权限集，不引入多角色。权限中间件示例为 `AdminPermission`，路由接入时将权限编码作为中间件参数传入，例如 `user:list`。权限表未初始化时默认拒绝具体业务权限；认证接口 `me` 仍可返回空的权限集合。

前端路由的 `meta.permission` 和 `v-permission` 只负责体验层控制；401 必须回登录页，403 必须显示无权页面，不能把权限不足误判为登录失效。

## PHP 后端扩展

1. 将示例控制器、逻辑、模型和中间件按目标 ThinkPHP 项目的模块结构接入；按项目版本调整命名空间、依赖注入及响应 API。
2. 在实际路由文件注册明确 API 路由，并放在 Vue history 的 GET 回退规则之前。
3. 每个受保护的业务控制器都必须应用管理员鉴权中间件；不要把前端隐藏菜单或路由守卫当成权限控制。
4. 业务实现放在逻辑层；校验输入并限制分页、排序等可控参数。错误响应不得向客户端暴露 SQL、文件路径、堆栈或密钥。
5. `UserController.php` 仅为业务扩展示例，依赖本模板未提供的 `UserLogic` 和用户表，接入时必须替换为项目自己的实现。

## 文档与变更

- 文档按模块拆分维护（见 [`README.md`](./README.md) 文档地图）：每个主题一个文件，单文件聚焦单一主题；新增文档须登记到文档地图。
- 根目录 `README.md` 负责项目概览和快速入口；详细框架使用说明以 `doce/README.md` 为唯一索引，避免重复维护。
- 新增配置、接口、部署方式或主题/布局预设时，同步更新对应文档及代码注释。
- 修改后至少执行 `npm run build`；PHP 文件使用 `php -l` 检查语法。
